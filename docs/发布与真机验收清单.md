# GeoMix Extension MVP 发布与真机验收清单

> **适用版本**：GeoMix Extension MVP（Manifest V3，支持 Chrome / Edge Chromium 桌面浏览器）
> **关联文档**：[`AGENTS.md`](../AGENTS.md)、[`docs/GeoMix-Extension-MVP需求与架构设计.md`](./GeoMix-Extension-MVP需求与架构设计.md)、Issue `#6` / `#7`
> **安全与合规红线（发版前强制逐项确认）**：
> 1. **严禁读取或上传第三方平台 Cookie**（无 `cookies` 权限、无 `document.cookie` 调用）；
> 2. **严禁自动点击任何平台的最终「发布 / 提交审核」按钮**（最高权限仅限填充草稿与本地转存图片，最终发布由人工审阅并手动点击）；
> 3. **最小化 MV3 权限**（仅 `storage` / `tabs` / `activeTab` / `scripting` + 精确 5 个平台 `host_permissions` + 按需 `optional_host_permissions: ["https://*/*"]`，零 `<all_urls>` / `http://*/*` / `web_accessible_resources`）；
> 4. **公网 URL 白名单回传与脱敏规范**（仅回传清洗后的公开文章 HTTPS URL，所有文档/截图/测试严禁出现真实域名、真实账号、真实品牌名或真实 `gmext_` Token）。

## 一、环境准备、质量门禁与 CWS 干净 ZIP 打包

### 1.1 前置环境

- Node.js `>= 22.0.0`
- `pnpm`（与 `package.json` 锁定的依赖树一致）
- 目标真机浏览器：Google Chrome（最新稳定版）或 Microsoft Edge（Chromium 内核）

### 1.2 自动化质量门禁（发版前必须全绿）

```bash
pnpm install --frozen-lockfile
pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm format:check
```

说明：
- `pnpm test` 已覆盖所有单元与 DOM Fixture 测试、`tests/manifest-security.spec.ts`（Manifest 权限与静态红线守卫）以及 `tests/bridge-e2e.spec.ts`（Mock Bridge 三平台全链路集成回归）。
- `pnpm build` 执行双通道构建：主入口与 Service Worker（`dist/background.js`、`dist/popup/index.html`、`dist/manifest.json`、`dist/icons/`）+ IIFE 单文件注入脚本（`dist/content.js`，内联三大平台 Adapter 且无 `.map` 产物）。

### 1.3 CWS 干净 ZIP 打包与自检

> **注意**：请务必执行 `pnpm run pack` 或 `node scripts/pack.mjs`。**切勿**直接执行不带 `run` 的 `pnpm pack`（那是 pnpm 内置的 npm `.tgz` 打包命令，会在仓库根目录生成无关 `.tgz` 包）。

```bash
# 方式 A：默认输出至 release/geomix-extension-v<version>.zip（已被 .gitignore 的 *.zip 忽略）
pnpm run pack

# 方式 B：指定自定义输出路径（例如输出至临时目录供发版上传）
node scripts/pack.mjs --out /tmp/geomix-extension-release.zip
```

执行压缩包结构与完整性自检：

```bash
unzip -t release/geomix-extension-v0.1.0.zip
unzip -l release/geomix-extension-v0.1.0.zip
git status --porcelain
```

核对清单：
- [ ] `unzip -t` 全部条目校验通过（`No errors detected`）；
- [ ] `unzip -l` 确认根目录直接为 Chrome 可加载结构：`manifest.json`、`background.js`、`content.js`、`popup/index.html`、`icons/icon-16.png`、`icons/icon-32.png`、`icons/icon-48.png`、`icons/icon-128.png`（无 `dist/` 外层包裹目录，无 `./` 前缀）；
- [ ] `unzip -l` 确认**零** `.map`、`*.spec.*`、`*.test.*`、`fixtures.*`、`.ts`/`.tsx`/`.jsx`、`.DS_Store`、`Thumbs.db`、`.env*` 或 `src/`/`tests/` 源码文件；
- [ ] `git status --porcelain` 确认仓库工作区无任何 `.zip`、`.crx`、`.tgz` 或构建垃圾文件。

## 三、Token 配对、按需域名授权与 401 吊销解绑验收

以下验收均使用脱敏占位示例（实际真机验收时替换为你自部署的测试实例地址与测试 Token，**切勿**将真实域名或 Token 截图/复制到公仓 Issue/PR）：
- 示例 GeoMix 服务地址：`https://geo.example.com`
- 示例配对 Token：`gmext_demo_token_example_0001`

核对清单：
- [ ] **非法输入本地拦截**：输入 `http://geo.example.com`（非 HTTPS）、`https://localhost`、内网 IP（如 `https://192.168.1.10`）或非 `gmext_` 前缀 Token 时，Popup 本地即时拦截并提示规范错误，不发起网络请求；
- [ ] **`optional_host_permissions` 拒绝分支**：输入合法 HTTPS 地址与 Token，点击「验证并配对」，在浏览器弹出的按需站点授权弹窗中点击「拒绝（Deny）」，确认 Popup 提示「未授予该域名访问权限」且未写入本地凭证；
- [ ] **`optional_host_permissions` 允许与 `/me` 配对**：重新点击「验证并配对」并在授权弹窗点击「允许（Allow）」，确认请求 `GET /api/v2/extension/me`（携带 `Authorization: Bearer ...` 与 `X-GeoMix-Extension-Version`）成功；顶部正确展示账号昵称（如 `DemoOperator`）、Token 标签与前缀、有效期，以及 CN 品牌筛选下拉框（如 `DemoBrand`）；
- [ ] **Token 安全存储自查**：
  - 打开 Popup DevTools → Application → Storage，确认仅 `chrome.storage.local` 含 `geomix.pairing.v1`；
  - 确认宿主网页 `localStorage` / `sessionStorage`、DOM 节点及 SW / Content Console **均零明文 `gmext_` 输出**；
- [ ] **待发任务队列与筛选**：确认 `GET /api/v2/extension/tasks` 正确拉取 `L2_EXTENSION` 任务列表，支持按 CN 品牌与平台（知乎 / 今日头条 / 什么值得买）筛选，每张卡片清晰展示标题、渠道标签、状态与「防封提示清单（`complianceChecklist`）」；
- [ ] **`401` 吊销降级与一键解绑**：
  - 在 GeoMix 后台吊销当前测试 Token 后，点击「刷新队列」或在页面浮条点击回传，确认界面展示含 `401` 的友好失效提示并引导重新配对（不崩溃、不泄漏明文 Token）；
  - 点击「重新配对」：确认 `chrome.storage.local`（`geomix.pairing.v1`）被**立即清空**并回到配对表单，同时在同账号 `401` Token 轮换期间保留 `chrome.storage.session`（`geomix.tabTasks.v1`）以便已发布的活跃标签页重试回传；重新提交新 Token（`PAIR_ACCOUNT`）后，系统自动按新账号已授权品牌列表裁剪越权标签页绑定记录；
  - 点击「解除绑定」：确认 `chrome.storage.local`（`geomix.pairing.v1`）与 `chrome.storage.session`（`geomix.tabTasks.v1`）均被**立即清空**，界面回到配对表单。

## 四、三大内容平台真机冒烟验收清单

> **统一前置**：每平台均需先执行一次**未登录态负向验证**（无痕窗口或未登录浏览器配置文件），确认返回 `AUTH_REQUIRED` 且不篡改编辑区、不崩溃；随后再在已人工登录创作者账号的本地浏览器执行正向草稿注入验收。

### 4.1 知乎（`ZHIHU_EXT`）

#### A. 知乎专栏模式（`https://zhuanlan.zhihu.com/write`）
- [ ] **未登录态检测**：未登录或弹出 SignFlow 登录弹窗时，返回 `AUTH_REQUIRED` 并提示运营先在本地浏览器完成知乎登录；
- [ ] **标题与正文注入**：点击「写入草稿箱」后自动打开/复用专栏编辑页，React 受控标题输入框与 Draft.js 富文本正文完整填入（刷新或轻触编辑区后标题不回滚丢失）；
- [ ] **配图本地中转**：文章配图经扩展上下文拉取后通过原生上传通道写入知乎图床，正文中无残留第三方外链 `<img>`；
- [ ] **严禁自动发布红线**：仅保持知乎自动保存草稿态，**绝不自动点击「发布 / 发布文章 / 确认发布」**；
- [ ] **草稿页与公网页区分**：停留在 `/write` 或 `/p/<数字ID>/edit` 草稿页时不弹出回传浮条；人工审阅并手动点击「发布」跳转至 `https://zhuanlan.zhihu.com/p/<数字ID>` 后，右下角自动弹出 Shadow DOM 捕获确认浮条。

#### B. 知乎问题回答模式（`targetUrlHint`）
- [ ] **有效问题链接路由**：当任务携带有效 `targetUrlHint`（如 `https://www.zhihu.com/question/987654321`）时，点击「写入草稿箱」直接打开或复用该问题页并在回答编辑器内注入正文与配图；
- [ ] **非法 `targetUrlHint` 回退**：若 `targetUrlHint` 非有效知乎问题链接，安全回退至 `https://zhuanlan.zhihu.com/write`；
- [ ] **回答公网 URL 捕获**：人工点击发布回答后跳转至 `https://www.zhihu.com/question/<数字ID>/answer/<数字ID>` 时正确捕获并清洗公网 URL。

### 4.2 今日头条（`TOUTIAO_EXT`）

入口：`https://mp.toutiao.com/profile_v4/graphic/publish`（兼容已保存草稿页 `https://mp.toutiao.com/profile_v4/graphic/edit`）

- [ ] **未登录态检测**：页面重定向至头条号/SSO 登录页时，返回 `AUTH_REQUIRED`；
- [ ] **标题与 ProseMirror 正文注入**：已登录时正确注入标题与富文本正文，排版结构（标题层级、列表、引用块）完整保留；
- [ ] **配图原生转存**：配图经原生文件上传或粘贴通道转存至头条图床，无第三方防盗链外链残留；
- [ ] **安全草稿保存红线**：如页面存在严格白名单匹配的「存草稿 / 保存草稿」按钮则仅保存草稿；**绝不自动点击「预览并发布」「发布」「定时发布」「提交审核」**；
- [ ] **公网 URL 捕获与后台隔离**：停留在 `mp.toutiao.com` 后台任意路径时不弹出回传浮条；人工审阅手动发布并打开公网文章页 `https://www.toutiao.com/article/<数字ID>` 或 `https://www.toutiao.com/i<数字ID>` 时弹出 Shadow DOM 捕获确认浮条。

### 4.3 什么值得买（`SMZDM_EXT`）

入口：`https://post.smzdm.com/tougao/`

- [ ] **未登录态检测**：未登录或出现值友登录弹窗时返回 `AUTH_REQUIRED`；
- [ ] **长文、参数对比表格与实测数据块保真**：已登录时注入标题与正文，完整保留**参数对比表格（`<table>` / `<thead>` / `<tbody>` / 合并单元格）**与**实测数据块**，同时过滤不安全脚本/内联事件且无外部外链 `<img>`；
- [ ] **安全草稿保存红线**：仅触发严格白名单「保存草稿」按钮或保留草稿态，**绝不自动点击「提交审核」「发布」**；
- [ ] **专属人工复核提醒（Mode B 浮条 + Popup 反馈）**：
  - [ ] 明确提醒运营人工核对并插入对应站内**商品卡片**（型号、价格与购买链接）；
  - [ ] 明确提醒运营人工核对文末**合规披露声明**（利益相关说明、体验来源与实测条件）；
- [ ] **公网 URL 捕获与投稿页隔离**：停留在 `https://post.smzdm.com/tougao/`（含 `?draft_id=...`）时不弹出回传浮条；人工提交并过审后访问 `https://post.smzdm.com/p/<字母数字ID>` 时弹出 Shadow DOM 捕获确认浮条。

## 五、图片防盗链本地中转与部分失败降级（Mode B）验收

- [ ] **正常防盗链中转**：任务包含 `https://cdn.example.com/...` 配图（PNG / JPEG / WebP）时，由 Background Service Worker 拉取二进制（仅允许公网 HTTPS、单图 `≤ 10MB`、超时 `15s`、最大并发 `≤ 2`、拒绝私网/内网重定向与非光栅图片 MIME），经 Content Script 重建 `File` 对象通过 `<input type="file">` 或 `DataTransfer` 粘贴上传；
- [ ] **部分/全部失败降级（Mode B 提醒浮条）**：构造包含 1 张 `HTTP 403` 或超时/超 `10MB` 图片的测试任务，确认：
  - 正文仍完整写入草稿（返回 `stage: 'PARTIAL_MEDIA_FAILED'`），绝不静默丢图、绝不把原始防盗链外链 URL 塞入正文；
  - 页面右下角自动弹出 Shadow DOM「GeoMix 草稿写入提醒」浮条，清晰展示成功张数、失败张数及每张失败配图的 `alt`、脱敏 URL（已剥离 Query/Hash）与失败原因，便于运营手动补传。

## 六、Shadow DOM 公网 URL 捕获浮条（Mode A）、URL 规范化与幂等回传验收

- [ ] **Shadow DOM 样式隔离**：打开 DevTools 检查 `#geomix-extension-capture-host`，确认挂载于 Shadow Root 内且包含 `:host { all: initial; }`，既不受宿主平台全局 CSS 污染，也不破坏宿主页面排版；可随时点击关闭按钮隐藏；
- [ ] **整页跳转与 SPA 路由监听**：人工发布后无论是整页重定向还是 SPA `pushState` / `replaceState` / `popstate` 路由切换至目标公网文章页（即使期间 MV3 Service Worker 发生休眠重启），浮条均能从 `chrome.storage.session` 恢复任务上下文并自动弹出；
- [ ] **URL 规范化与非法链接拦截**：
  - 访问带追踪参数的公网链接（如 `?utm_source=demo&share_code=xyz#comments`），确认浮条展示与回传的 `publishedUrl` 已自动剥离 Query 与 Hash；
  - 访问编辑页草稿 URL 或跨平台文章 URL 时不弹出回传浮条；
  - 关闭尚未发布的草稿标签页后，`chrome.storage.session` 对应 Tab 绑定自动清理，避免后续打开新标签产生幽灵浮条；
- [ ] **幂等回传与归因闭环**：
  - 点击「一键回传至 GeoMix 开启 T+7/14/30 追踪」（并测试快速连点两次），确认仅触发有效提交且请求 `POST /api/v2/extension/tasks/:taskId/confirm-published` 携带 `Authorization`、`X-GeoMix-Extension-Version` 与确定性 `Idempotency-Key`；
  - 重试提交不产生重复发布记录；回传成功后浮条展示 `publishRecordId`、`T+1 抓取探针已排队` 与 `T+7 / T+14 / T+30 复测已预约`，并在 GeoMix 主控制台确认任务状态更新为 `PUBLISHED`。

## 七、Chrome Web Store（CWS）隐私披露与权限说明提交模板

> 以下文案可直接用于 Chrome Web Store Developer Dashboard 的 **Privacy practices** 与 **Permissions justification** 审核栏位。

### 7.1 单一用途说明（Single Purpose Description）

- **English (Recommended for CWS Review)**：
  > GeoMix Channel Draft Helper has a single purpose: helping authenticated GeoMix users inject their prepared content variants into local draft editors on Zhihu, Toutiao, and SMZDM, and—strictly after manual human review and manual publishing—reporting the resulting public article URL back to the user's configured GeoMix instance for publication attribution tracking.
- **中文参考**：
  > GeoMix 渠道草稿助手仅用于单一明确用途：协助已配对的 GeoMix 用户将待发渠道变体写入本地已登录浏览器的知乎、今日头条、什么值得买草稿箱，并在用户人工审阅且手动点击发布后，将清洗后的公开文章链接回传至用户自行配置的 GeoMix 服务以开启归因追踪。

### 7.2 权限最小化逐项说明表（Permissions & Host Permissions Justification）
